# AI 영상 편집 — 공통 뼈대

프로그램마다 **연결 방식만 다르고**, 무음 감지·받아쓰기·자막 분할·모션그래픽 렌더는 전부 같다.
그 공통 부분과 검증 규칙이 여기 있다. 프로그램 고유 조작은 어댑터 스킬에 있다.

## 1) 어느 프로그램인가 — 먼저 정한다

| 프로그램 | 어댑터 스킬 | 연결 방식 |
|---|---|---|
| Adobe Premiere Pro | `premiere-auto-edit` | MCP + ExtendScript — **실시간** 반영 |
| CapCut (캡컷) | `capcut-auto-edit` | draft JSON 파일 편집 — **앱 종료 후** 반영 |
| Final Cut Pro (파이널컷) | `finalcut-auto-edit` | FCPXML 생성 → 임포트 — **보관함 선택 클릭** 필요 |

- 사용자가 프로그램을 밝히지 않았으면 **묻는다**. 추측해서 진행하지 않는다.
- 어댑터를 정했으면 그 스킬의 SKILL.md를 읽고 **그쪽 절차를 따른다**.
- 목록에 없는 프로그램을 요청받으면 아래 "새 프로그램" 절을 따른다.

## 2) 공통 분석 도구 (프로그램 무관)

Claude는 영상을 직접 보거나 들을 수 없다. 아래 도구로 **정보를 뽑고**, 그 정보를 가지고
어댑터가 **편집을 실행**한다.

### 무음 구간 감지
```bash
bash ~/.claude/skills/ai-video-edit/scripts/detect_silence.sh "<영상경로>" <dB> <최소초> [pad]
# 예: ... "/path/clip.mov" -30 2.0      → /tmp/premiere_cuts.json 에 컷 목록
```
사용자가 "n dB 이하", "n초 이상"을 지정하면 그대로 반영한다. 기본값은 -30dB / 2.0초.

### 단어 단위 받아쓰기
```bash
python3 ~/.claude/skills/ai-video-edit/scripts/transcribe_words.py <오디오> --lang ko --workdir <WORK>
```
- faster-whisper `word_timestamps=True`. whisper.cpp 는 타임스탬프가 부정확해 쓰지 않는다.
- ⚠️ python3 가 anaconda 로 잡히면 faster-whisper 가 없다.
  `/Library/Frameworks/Python.framework/Versions/3.14/bin/python3` 를 명시적으로 쓴다.

### 쉼 기반 자막 분할
```bash
python3 ~/.claude/skills/ai-video-edit/scripts/segment_subtitles.py --workdir <WORK> --soft 16 --gap 0.4
```
말이 나올 때만 자막이 뜨도록 쉼 구간에서 끊는다. 최소 표시 0.5초.

### 모션그래픽 렌더
`hyperframes` 로 HTML+GSAP → **ProRes 4444 알파 MOV**. 설치 불필요(`npx hyperframes`).
- 프리미어·캡컷 **둘 다 알파 MOV 를 지원**한다. 같은 렌더를 양쪽에 재사용한다.
- 캔버스 비율을 맞춘다. 세로 영상이면 세로로 렌더한다(2160×3840 등).

## 2-1) 사용자가 조정을 요청할 때 — 기본값을 고집하지 않는다

기본값은 **출발점일 뿐**이다. 사용자가 결과를 보고 조정을 요청하면 바로 다시 돌린다.
"다시 해드릴까요?" 라고 되묻지 말고, 어떤 값을 어떻게 바꿨는지 말하면서 실행한다.

### 무음 감지 — `detect_silence.sh <영상> <dB> <최소초> [패딩]`

| 사용자가 이렇게 말하면 | 조정 |
|---|---|
| "너무 많이 잘렸어" / "말이 끊겨" | 임계를 낮춘다(-30 → -40), 최소초를 늘린다, 패딩을 늘린다(0.08 → 0.15) |
| "덜 잘렸어" / "빈 곳이 남아" | 임계를 높인다(-30 → -25), 최소초를 줄인다(2.0 → 0.5) |
| "n dB 이하", "n초 이상" | 그대로 반영 |
| "숨소리까지 다 빼줘" | -40dB / 0.3초 정도로 공격적으로 |

### 자막 분할 — `segment_subtitles.py --soft <자> --gap <초>`

| 사용자가 이렇게 말하면 | 조정 |
|---|---|
| "자막이 너무 짧게 끊겨" | `--soft` ↑ (16 → 24), `--gap` ↑ (0.4 → 0.7) |
| "한 줄이 너무 길어" | `--soft` ↓ (16 → 12) |
| "말이 끝날 때까지 붙여줘" | `--gap` ↑ (0.4 → 1.0) |
| **세로 영상(9:16)** | 화면이 좁으니 `--soft 12~14` 가 적당. 가로는 16~20. |

### 받아쓰기 — `transcribe_words.py --lang <코드> --model <모델>`

| | |
|---|---|
| 다른 언어 | `--lang en` 등 |
| 더 빠르게 | `--model medium` (정확도는 떨어진다) |
| 기본 | `large-v3` — 한국어 정확도가 확실히 낫다 |

**조정 후에는 무엇이 달라졌는지 수치로 보고한다** (자막 9개 → 5개, 평균 1.1초 → 2.0초).

## 3) 검증 프로토콜 — "됐다"고 말하기 전에

**실행 → 읽기로 실제 상태 재확인 → 판정.** 실행이 에러 없이 끝난 것은 근거가 아니다.

| 대상 | 확인 방법 |
|---|---|
| 컷 | 클립 개수·전체 길이를 다시 읽어 비교 |
| 자막 | 트랙에 세그먼트가 실제로 있는지 + 시작/끝 시각 |
| 그래픽·애니메이션 | **눈으로 본다.** export → ffmpeg 프레임 추출, 또는 사용자에게 확인 요청 |
| 파일 편집 방식 | 적용 직후 해시 vs 앱을 연 뒤 해시 — 다르면 앱이 덮어쓴 것 |

🚨 **애니메이션·그래픽은 API 응답을 믿지 않는다.** 프리미어 키프레임은 `getValueAtKey()` 가
값을 돌려주는데도 렌더에서 무시된 전례가 있다. 반드시 시각 확인한다.

🚨 **변화가 미묘하면 판별이 안 된다.** 검증용 테스트는 **극단값**으로 한다
(크기 15%, 180도 회전, 불투명도 5%). 사용자가 "잘 모르겠다"고 하면 값을 더 극단으로 키운다.

## 4) 실패했을 때 — 1회 실패로 ❌ 판정하지 않는다

판정 전에 아래를 전부 소진한다.

1. 다른 API/경로가 있는가 (MCP 기본 도구 대신 직접 스크립트 등)
2. 앱이 실행 중이라 덮어쓴 것은 아닌가 (파일 편집 방식)
3. 함께 고쳐야 할 **짝**을 빠뜨리지 않았나 (material, 등록부, 미러 파일)
4. 시간/길이 관련 필드를 다시 계산했나
5. 파일 권한 문제는 아닌가 — macOS 는 데스크탑/문서/다운로드를 TCC 로 막는다
6. 값이 미묘해서 못 알아본 것은 아닌가 → 극단값 재시도
7. 같은 문제를 겪은 사례가 밖에 있는가 → **검색한다**

> 실제로 이 목록의 1·2·3·5·7 이 각각 며칠짜리 문제를 풀었다.
> 특히 7번: CSInterface CEP 12 버그는 GitHub 이슈에서, 캡컷 리소스 ID는
> 오픈소스 카탈로그에서 찾았다. 막히면 밖을 본다.

**독립 검증을 만들 때 의심 대상 의존성을 재사용하지 않는다.** 진단 패널이 문제의
CSInterface.js 를 그대로 복사해 "시스템 고장"이라고 오판한 적이 있다.

## 5) 목록에 없는 기능을 요청받았을 때 — 만들어서 쓴다

거절하지 않는다. 다음 순서로 진행한다.

1. **안내** — "이 기능은 아직 검증 안 됐습니다. 만들어서 시도해볼까요?"
2. **동의** 를 받는다
3. **제작** — 어댑터의 `references/recipes.md` 에 있는 검증된 패턴을 조합
4. **검증** — 위 3절 프로토콜대로. 실패하면 4절 체크리스트를 소진
5. **기록** — 성공/실패 모두 어댑터의 `recipes.md` 에 코드와 함께 남긴다.
   실패는 **시도한 접근 목록**까지 적어 다음에 같은 삽질을 반복하지 않게 한다.

## 6) 새 프로그램을 추가할 때

목록에 없는 편집 프로그램을 요청받으면, **어댑터 하나만** 새로 만든다.
공통 분석·검증·자가확장 규칙은 이 스킬을 그대로 쓴다.

어댑터가 정해야 하는 것은 연결 계층뿐이다:

1. **어떻게 닿는가** — 플러그인/스크립팅 API? 프로젝트 파일 편집? CLI?
2. **언제 반영되는가** — 실시간? 앱 재시작 후?
3. **안전장치** — 백업, 앱 실행 중 가드
4. **검증 매트릭스** — `references/recipes.md` 에 기능별 ✅/⬜/❌ 와 코드

조사할 때는 이 순서로 소진한다(캡컷에서 실제로 쓴 경로):
공식 API/플러그인 → 스크립팅 브리지(AppleScript/COM) → 디버그 포트(CDP 등) →
IPC 소켓 → **프로젝트 파일 직접 편집** → 오픈소스 선례 검색.
